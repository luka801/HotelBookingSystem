=====================================================
სასტუმროს ჯავშნის სისტემა (Hotel Booking System) - C#
დეტალური ახსნა
=====================================================

------------------------------------------------------
1. რა შევქმენით
------------------------------------------------------

C#-ის საკონსოლო აპლიკაცია ერთი კონკრეტული სასტუმროსთვის
("Quiet Bay Hotel"), სადაც:

  - მომხმარებელს (User) შეუძლია:
      * ნახოს თავისუფალი ოთახები
      * დაჯავშნოს ოთახი (სახელით და თარიღებით)
      * ნახოს საკუთარი ჯავშნები
      * გააუქმოს საკუთარი ჯავშანი

  - ადმინისტრატორს (Admin, პაროლით: admin123) შეუძლია:
      * ნახოს ყველა ოთახი
      * დაამატოს ახალი ოთახი
      * წაშალოს ოთახი (თუ მასზე აქტიური ჯავშანი არ არის)
      * ნახოს ყველა ჯავშანი
      * დაადასტუროს ჯავშანი
      * გააუქმოს ნებისმიერი ჯავშანი

მონაცემები ინახება მხოლოდ მეხსიერებაში (List<>), მონაცემთა
ბაზა არ გამოიყენება - პროგრამის დახურვისას მონაცემები იშლება.
ეს განზრახ არის გაკეთებული ასე, რადგან თქვენი ლექცია
console აპლიკაციებზე იყო აწყობილი, ბაზის გარეშე.

3. თითოეული ფაილის დანიშნულება და აზრი
------------------------------------------------------

--- Models/Room.cs ---

განსაზღვრავს ერთი ოთახის მონაცემებს: Id, Number, Type
(Standard/Deluxe/Suite), PricePerNight, IsAvailable.

მნიშვნელოვანი: ყველა property-ს აქვს "private set", ანუ
გარედან (მაგ. Program.cs-დან) შეუძლებელია ვინმემ პირდაპირ
დაწეროს room.IsAvailable = true. მონაცემები იცვლება მხოლოდ:
  - კონსტრუქტორით (ობიექტის შექმნისას)
  - MarkAsBooked() მეთოდით (როცა ოთახი იჯავშნება)
  - MarkAsAvailable() მეთოდით (როცა ჯავშანი უქმდება)

ეს არის ინკაფსულაცია (encapsulation) - საკუთარი მდგომარეობის
დაცვა არასასურველი, უკონტროლო ცვლილებებისგან. ცვლილება
ხდება მხოლოდ HotelService-ის კონტროლირებული ლოგიკით.


--- Models/Booking.cs ---

განსაზღვრავს ერთ ჯავშანს: Id, RoomId, GuestName, CheckIn,
CheckOut, Status (Pending/Confirmed/Cancelled). ასევე ითვლის
ღამეების რაოდენობას (Nights).

იგივე პრინციპით, ყველა property "private set"-ია, ხოლო
სტატუსის შეცვლა ხდება მხოლოდ Confirm() და Cancel() მეთოდებით.


--- Data/SeedData.cs ---

აქ არის ოთახების საწყისი სია გატანილი ცალკე ფაილში, რომ
HotelService "სუფთა" დარჩეს და მხოლოდ ლოგიკაზე იყოს
პასუხისმგებელი, არა კონკრეტულ მონაცემებზე.

თავდაპირველად ოთახები ხელით იყო ჩამოთვლილი (5 ცალი), მერე
თქვენი თხოვნით გადავაკეთეთ ციკლად (for loop), რომელიც
ავტომატურად აგენერირებს 120 ოთახს (TotalRooms კონსტანტა),
10 ოთახი სართულზე (RoomsPerFloor). ოთახის ტიპი და ფასი
ავტომატურად ირჩევა ნომრის მიხედვით:
  - ყოველი მე-5 ოთახი სართულზე -> Suite (220/ღამე)
  - ლუწი ნომრები -> Deluxe (130/ღამე)
  - დანარჩენი -> Standard (80/ღამე)

თუ გინდათ ოთახების რაოდენობის შეცვლა, საკმარისია შეცვალოთ
მხოლოდ ერთი რიცხვი: TotalRooms.


--- Services/HotelService.cs ---

ეს არის სისტემის "გული" - მთელი ბიზნეს-ლოგიკა ერთ ადგილას:

  - GetAllRooms() / GetAvailableRooms() / GetRoomById()
  - AddRoom() / RemoveRoom()
  - BookRoom() - ამოწმებს ხელმისაწვდომობასა და თარიღებს,
    ქმნის ახალ Booking-ს და ნიშნავს ოთახს დაკავებულად
  - CancelBooking() - აუქმებს ჯავშანს და ათავისუფლებს ოთახს
  - ConfirmBooking() - ადასტურებს ჯავშანს (მხოლოდ Pending
    სტატუსიდან)
  - GetAllBookings() / GetBookingsByGuest()

ID-ების ავტომატური ზრდა:
  _nextRoomId და _nextBookingId არის counter-ები, რომლებიც
  ყოველი ახალი ობიექტის შექმნისას ავტომატურად იზრდება ერთით
  (room = new Room(_nextRoomId++, ...)). ანუ არც ერთხელ არ
  არის საჭირო ID-ის ხელით შეყვანა. _nextRoomId თავიდანვე
  სწორად გამოითვლება საწყისი (seed) ოთახებიდან კონსტრუქტორში.


--- Config/AppSettings.cs ---

უბრალოდ ინახავს ადმინის პაროლს ერთ ადგილას (const string
AdminPassword = "admin123"), რომ არ იყოს "ჰარდქოდილი"
პირდაპირ Program.cs-ში ან AdminMenu-ში.


--- Helpers/InputHelper.cs ---

საერთო, თავიდან ხელახლა-გამოსაყენებელი (reusable) მეთოდები
Console-იდან უსაფრთხო წაკითხვისთვის:
  - ReadString(prompt)
  - ReadInt(prompt) -> int? (null თუ არასწორია)
  - ReadDecimal(prompt) -> decimal? (null თუ არასწორია)
  - ReadDate(prompt) -> DateTime (მანამ სთხოვს, სანამ სწორ
    ფორმატს არ შეიყვანს: dd.MM.yyyy)

ეს საჭირო გახდა, რადგან UserMenu-ც და AdminMenu-ც ორივე
იყენებდნენ თითქმის იდენტურ int.TryParse/decimal.TryParse
კოდს - ერთ ადგილას გატანით აღარ მეორდება იგივე ლოგიკა.


--- UI/WelcomeScreen.cs ---

მხოლოდ ბეჭდავს მისალმების ბანერს პროგრამის გაშვებისას.
წმინდა კოსმეტიკური ფაილია, გატანილია რომ Program.cs
ზედმეტად არ დაიტვირთოს.


--- UI/UserMenu.cs ---

მთელი მომხმარებლის მენიუს ლოგიკა ერთ კლასშია თავმოყრილი:
Show() მეთოდი აჩვენებს მენიუს და switch-ით მართავს არჩევანს,
ხოლო კონკრეტული ქმედებები (ShowAvailableRooms, MakeBooking,
ShowMyBookings, CancelMyBooking) არის private მეთოდები იმავე
კლასში. კლასი იღებს HotelService-ს კონსტრუქტორში
(dependency injection-ის მარტივი ფორმა).


--- UI/AdminMenu.cs ---

იგივე პრინციპით, მთელი ადმინის მენიუს ლოგიკა: Show() მეთოდი
ჯერ ითხოვს პაროლს (AppSettings.AdminPassword-თან
შედარებით), შემდეგ აჩვენებს მენიუს. კონკრეტული ქმედებები
(ShowAllRooms, AddRoom, RemoveRoom, ShowAllBookings,
ConfirmBooking, AdminCancelBooking) - ცალკე private
მეთოდები.


--- Program.cs ---

მას შემდეგ რაც ყველაფერი გავიტანეთ ცალკე ფაილებში, Program.cs
დარჩა ძალიან მოკლე და მარტივი (~35 ხაზი):

  1. ქმნის HotelService-ის ერთ ინსტანციას (var hotel = ...)
  2. აჩვენებს მისალმებას (WelcomeScreen.Show)
  3. ქმნის UserMenu და AdminMenu ობიექტებს, გადასცემს hotel-ს
  4. უშვებს მთავარ მენიუს (while loop), სადაც უბრალოდ ეძახის
     userMenu.Show() ან adminMenu.Show() არჩევანის მიხედვით

Program.cs აღარ იცის რა ხდება მენიუების შიგნით - ის მხოლოდ
"აწყობს" (wire-ავს) სისტემის ნაწილებს ერთმანეთთან.


------------------------------------------------------
4. რატომ გავყავით ასე (არქიტექტურული პრინციპი)
------------------------------------------------------

მთელი პროცესი მიჰყვებოდა ერთ პრინციპს: Single Responsibility
Principle (SRP) - თითოეულ კლასს/ფაილს ჰქონდეს ერთი, მკაფიო
პასუხისმგებლობა:

  - Models   -> მხოლოდ მონაცემების სტრუქტურა
  - Data     -> მხოლოდ საწყისი მონაცემები
  - Services -> მხოლოდ ბიზნეს-ლოგიკა
  - Helpers  -> მხოლოდ დამხმარე, ხელახლა გამოსაყენებელი კოდი
  - Config   -> მხოლოდ პარამეტრები/კონსტანტები
  - UI       -> მხოლოდ მომხმარებელთან ურთიერთობა (Console)
  - Program  -> მხოლოდ ყველაფრის ერთმანეთთან დაკავშირება

ამის შედეგად:
  - კოდის წაკითხვა და გაგება გაცილებით მარტივია
  - შეცვლა/დამატება (მაგ. ახალი ტიპის ოთახი, ახალი მენიუს
    პუნქტი) აღარ საჭიროებს მთელი ფაილის მოძებნას
  - ტესტირება უფრო მარტივია, რადგან თითოეული ნაწილი
    დამოუკიდებელია დანარჩენებისგან


------------------------------------------------------
5. როგორ გავუშვათ პროექტი
------------------------------------------------------

1. შექმენით საქაღალდე HotelBookingSystem და მასში ქვე-
   საქაღალდეები: Config, Helpers, Models, Data, Services, UI
2. ყველა მიღებული .txt ფაილი გადაარქვით შესაბამის სახელზე
   (.cs ან .csproj გაფართოებით) და მოათავსეთ სწორ საქაღალდეში
3. ტერმინალიდან, პროექტის ძირითადი საქაღალდიდან:
       dotnet run
4. ან გახსენით .csproj ფაილი Visual Studio-ში/Rider-ში და
   გაუშვით პროგრამა (F5)
